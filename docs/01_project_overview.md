# 1. Огляд проєкту

## 1.1. Призначення
**AI Humanizer** — вебзастосунок для переформулювання тексту за допомогою моделей штучного інтелекту. Користувач вводить текст, обирає AI-модель і стиль обробки (промпт), після чого отримує переформульований результат.

Застосунок також підтримує створення власних промптів і перегляд історії попередніх операцій.

## 1.2. Мета
Розробити вебзастосунок, який забезпечує зручну взаємодію з моделями штучного інтелекту для переформулювання тексту, дозволяє обирати стиль обробки та зберігає результати виконаних операцій.

## 1.3. Завдання
- створити вебінтерфейс введення та відображення тексту;
- реалізувати серверну частину на Flask;
- організувати зберігання даних у SQLite;
- інтегрувати Hugging Face Inference Router;
- підключити декілька AI-моделей;
- реалізувати стандартні та користувацькі промпти;
- зберігати результати гуманізації в історії;
- створити JSON API для взаємодії Frontend і Backend;
- перевірити основні сценарії тестами.

## 1.4. Функціональні можливості
### Гуманізація
Користувач вводить текст, обирає модель і промпт, запускає обробку та переглядає результат. Результат можна скопіювати. Максимальна довжина вхідного тексту — 5000 символів; обмеження перевіряється у Frontend та API.

### Промпти
Доступні стандартні промпти та створення, перегляд, редагування й видалення власних промптів. Стандартні промпти доступні для перегляду, але не для редагування чи видалення. Початково створюються стилі Natural, Academic, Professional, Casual, Simple і Creative.

### Історія
Після успішної операції зберігаються початковий текст, результат, модель, ідентифікатор промпту, знімок його вмісту, час обробки та дата. Інтерфейс показує записи й підтримує пошук за початковим текстом, результатом, ідентифікатором моделі та назвою промпту.

Backend має DELETE endpoint історії, але кнопки видалення в інтерфейсі немає.

## 1.5. Ідентифікація клієнта
Реєстрація й авторизація не реалізовані. Браузер генерує UUID через `crypto.randomUUID()` і зберігає його в `localStorage` під ключем `ai_humanizer_client_id`. Ідентифікатор використовується API для фільтрації промптів та історії. Це спрощене розмежування даних, а не повноцінна автентифікація або гарантія безпеки.

## 1.6. Обмеження
- Для AI-функцій потрібен дійсний Hugging Face token.
- Доступність і якість генерації залежать від моделі та провайдера.
- Максимальна довжина вхідного тексту — 5000 символів.
- Використовується SQLite.
- Система облікових записів користувачів відсутня.
