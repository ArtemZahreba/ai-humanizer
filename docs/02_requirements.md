# 2. Вимоги до системи

## 2.1. Функціональні вимоги

| ID | Вимога | Реалізація |
|---|---|---|
| FR-01 | Відображення головної сторінки | `GET /` |
| FR-02 | Перелік AI-моделей | `GET /api/models` |
| FR-03 | Перелік доступних промптів | `GET /api/prompts` |
| FR-04 | Гуманізація тексту | `POST /api/humanize` |
| FR-05 | Обмеження довжини тексту | 5000 символів у Frontend та API |
| FR-06 | Відображення результату | JSON-відповідь API |
| FR-07 | Збереження результату | `humanization_history` |
| FR-08 | Перегляд історії | `GET /api/history` |
| FR-09 | Пошук в історії | Клієнтська фільтрація завантажених записів |
| FR-10 | Створення промпту | `POST /api/prompts` |
| FR-11 | Перегляд промпту | `GET /api/prompts/<id>` |
| FR-12 | Редагування промпту | `PUT /api/prompts/<id>` |
| FR-13 | Видалення промпту | `DELETE /api/prompts/<id>` |
| FR-14 | Перемикання теми | JavaScript та `localStorage` |
| FR-15 | Копіювання результату | Clipboard API |

## 2.2. Нефункціональні вимоги
- Інтерфейс має надавати доступ до Humanization, Prompts і History.
- Вибрана тема зберігається в браузері.
- Верстка адаптується до вузьких екранів через CSS media queries.
- Тривалість генерації залежить від зовнішнього AI-провайдера.
- Час обробки вимірюється та записується до історії.
- Параметри API проходять перевірку типів і обов'язкових значень.
- Помилки AI-провайдера перетворюються на контрольовані JSON-відповіді.
- Hugging Face token читається зі змінної середовища `HF_TOKEN`.
- `client_id` не є засобом автентифікації.

## 2.3. Технологічні залежності
Python, Flask, Flask-SQLAlchemy, SQLAlchemy, SQLite, python-dotenv, OpenAI Python SDK, HTML, CSS і JavaScript. Точні версії необхідно звіряти з актуальним `requirements.txt` та середовищем розробки.
