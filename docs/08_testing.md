# 8. Тестування

## 8.1. Підхід
У репозиторії є тести API гуманізації, інтеграції гуманізації зі збереженням історії, DELETE API історії, API промптів та API моделей. Для HTTP-маршрутів використовується Flask test client. Зовнішні AI-виклики в тестах підміняються mock-об'єктами або тестовою реалізацією.

## 8.2. Тестові файли

| Файл | Перевірки |
|---|---|
| `test_humanization_api.py` | Успішна гуманізація, відсутній текст, некоректний ID моделі, відсутній промпт, помилки провайдера, перевищення 5000 символів |
| `test_humanization_history_integration.py` | Передача правильних даних для збереження історії |
| `test_delete_history_api.py` | Успішне видалення через API, відсутній запис, відсутній/некоректний client ID, серверна помилка |
| `test_prompts_api.py` | Отримання списку й окремого промпту, відсутній client ID, неіснуючий промпт |
| `test_models_api.py` | Список моделей, окрема модель, неіснуюча модель |

## 8.3. Перевірка обмеження довжини
Для `/api/humanize` перевіряється текст довжиною 5001 символ. Очікується HTTP 400 і повідомлення `Text must not exceed 5000 characters`.

## 8.4. Межі тестового покриття
Наявний `test_prompts_api.py` переважно перевіряє GET-сценарії. Повний CRUD, за повідомленням розробника, перевірявся вручну, але його не слід називати автоматизованим покриттям цього тестового файлу.

DELETE API історії покритий тестом, хоча відповідної кнопки в інтерфейсі немає.

## 8.5. Запуск

```bash
python -m tests.test_humanization_api
python -m tests.test_humanization_history_integration
python -m tests.test_delete_history_api
python -m tests.test_prompts_api
python -m tests.test_models_api
```

Результати для курсової записки потрібно підтвердити актуальним запуском і зафіксувати фактичні повідомлення тестів.
